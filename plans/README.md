## Recommended order & rationale

Do the **P1 security pair first** (001, 002) — highest leverage, small, clean verification.
001 is the single most important finding (proxy + file-writing WS exposed to the LAN).
Then the **cheap, low-risk wins**: 003 (one-op bug fix), 004 (CI gate — but run its Step 1
baseline first; it STOPs if the web app already has type/lint errors). Then the **larger
quality work**: 005 (web tests), 006 (symlink containment), 007 (dependency advisory).
Finally the **P3** items: 008 (docs/metadata) and 009 (a spike that may or may not produce a
follow-up plan).

## Findings considered and rejected (do not re-audit)

- **Remove "unused" `radix-ui` from `apps/web`** — NOT unused. It provides the kibo color
  picker's hue/alpha sliders (`Slider.Root/Track/Range/Thumb` in
  `apps/web/components/kibo-ui/color-picker/index.tsx`). Removing it breaks the picker.
- **Unhandled promise rejection in the `discoverFile` WS handler (`server.ts:710`)** — not a
  bug. `discoverFile` wraps its entire body in try/catch and returns `null`, so it never
  rejects; the missing `.catch` is harmless.
- **Kibo color-picker controlled-value RGB→HSL bug** — known/by-design. `apps/web/CLAUDE.md`
  documents that the controlled-value path is buggy and is worked around via `defaultValue` +
  a mount effect. Not worth fixing the unused path.
- **Color-picker "stale closure" footgun** — not a finding; the component is correct, this was
  parent-code hygiene with no concrete defect.
- **Remove `colorjs.io`** — entangled: it is used only by the vendored
  `lib/theme-engine/radix/generate-radix-colors.ts`, which is out of scope (verbatim Radix,
  `@ts-nocheck`). Can't remove without rewriting vendored code.
- **MCP `find_component` / `discoverFile` build a `RegExp` from input without escaping** — low
  severity (local, requires a connection; worst case is a thrown error or slow grep). Noted but
  not planned; could be a small hardening if 009/grep work touches this area.
- **File-size limit on theme writes, MCP auth token, config-perms-on-read, env-var-in-`ps`
  warnings** — low value under the local single-user trust model; the loopback bind (001) +
  DNS-rebinding protection (002) address the realistic attack surface.
- **God-file refactor of `batch-transform.ts` / `transform.ts` / `selection.ts`** — real
  tech debt (1500–1800 lines each, duplicated node-resolution paths) but L effort / MED-HIGH
  risk, and a poor fit for a low-context executor. Deferred deliberately: it should be preceded
  by characterization tests (003 and 009 begin building that net for the transform layer; the
  overlay would need its own before `selection.ts` is split). Revisit as a dedicated,
  test-first effort, not a handoff plan.
